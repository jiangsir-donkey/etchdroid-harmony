# 上架华为应用市场（个人开发者）合规清单

> 说明：本文基于公开法规与商店规则的通行做法整理，**规则会变**，动手前请在
> 华为开发者联盟 / 工信部相关页面核对最新要求。本文不构成法律意见，涉及软著、
> 备案等以官方口径为准。
>
> 一个前提要说清楚：**有些风险只能"合规处理"，不能"规避"。** 下面第 1 节列出的
> 几种"省事做法"不但规避不了，反而会把风险从"民事纠纷"升级为"侵权 + 下架 +
> 封号"。

---

## 1. 先说不能做的（这些"省事做法"风险最大）

| 想当然的做法 | 实际后果 |
| --- | --- |
| 删掉 LICENSE、把应用说成自己原创 | 违反 GPLv3，构成**著作权侵权**。上游可发律师函、可向华为投诉，华为核实后会下架并可能封禁开发者账号 |
| 抹掉应用内的作者署名（关于页的 "Developed by depau"） | 同上。GPLv3 明确要求保留版权声明与许可证，删除即违约 |
| 只发二进制、不公开源码 | GPLv3 §6 要求分发目标代码时提供对应源代码，否则你**无权分发**这个应用 |
| 沿用上游的名字/图标，让用户以为这是官方版 | 涉嫌**商标侵权 / 不正当竞争（混淆行为）**。这是最容易被上游投诉、也最容易被上架后下架的一条 |
| 用别人的软著证书或伪造材料过审 | 属于提交虚假材料，账号会被封禁，情节严重可能涉及法律责任 |
| 保持闭源（加密/混淆掉代码） | 不解决任何问题：GPL 是**传染性**许可证，只要代码来自 EtchDroid，整个应用就必须是 GPLv3 |

**关键事实：当前工程的 `.ets` 代码是上游 Kotlin 代码的逐文件移植，属于 GPLv3
意义上的"修改版本"，因此整个应用必须以 GPLv3 发布。** 如果你希望闭源上架，
唯一干净的路子是**不基于 EtchDroid 代码重写**（包括重写 UI 结构、文案、异常
体系），那是另一个项目，不是"规避"。

## 2. 上架前必须完成的行政手续（中国大陆 · 个人开发者）

| # | 事项 | 办理方 | 说明 |
| --- | --- | --- | --- |
| 1 | 开发者实名认证 | 华为开发者联盟 | 个人开发者需身份证实名；**上架的著作权人/主体必须与实名信息一致** |
| 2 | 计算机软件著作权登记证书（软著） | 中国版权保护中心 | 华为应用市场对大陆上架应用通常要求提供软著或等效权利证明，个人开发者同样需要。材料一般为：申请表、源程序前 30 页 + 后 30 页（每页约 50 行）、软件说明书。周期约 1–2 个月（可加急） |
| 3 | APP 备案（工信部） | 通过接入服务商 / 应用市场备案通道 | 2023 年起移动应用需完成备案，上架时填写备案号。个人可备案，需先确定备案主体与联系方式 |
| 4 | 隐私政策（公网 URL） | 自己 | 见 `docs/privacy-policy.md`，必须发布到公网可访问的页面 |
| 5 | 权限使用说明 | 上架时填写 | 本应用只有"后台运行"权限，说明写入耗时较长需要后台继续 |
| 6 | 应用名称与图标 | 自己 | **不得使用他人商标或与他人应用易混淆的名称/图标**（见第 3 节） |
| 7 | 兼容性与资质 | 华为 | 工具类应用一般无需特殊资质；不得上架需要资质但个人开发者不具备的类别 |

### 软著与 GPL 的关系（容易踩坑）

- 软著登记是**形式审查**，登记下来**不会**改变 GPLv3 的义务：你仍然必须开源、
  仍然必须保留上游署名。
- 登记时你主张的是**你对移植/改编部分的著作权**，**不能**声称整份代码是你独立
  原创。建议在软著的"软件说明书"里如实写明"本软件基于开源项目 EtchDroid
  (GPLv3) 移植"，避免虚假声明的风险。
- 想稳妥可以就具体流程咨询版权中心或代理机构。

### 3.3 必须改的两处（风险最高）

**① 应用名称与图标（高风险，已选定"保留 EtchDroid + 后缀"方案）**

现状（**已按当前方案改造完毕**）：

| 项目 | 状态 |
| --- | --- |
| 分发名称 | `EtchDroid 鸿蒙版`（`AppScope` + `entry` 的 `app_name`、`EntryAbility_label`） |
| 图标 | **上游原始图标，未做任何改动**（与上游 `ic_launcher.png` 逐字节相同；留档于 `design/upstream-icon-192.png`）。这是当前**最需要靠许可或改名解决**的一项：外观与官方 App 一致，最容易被认定为混淆 |
| 应用内声明 | 「关于」页固定显示"非官方移植，与上游开发者无关联、未获背书"+ GPLv3 源码链接 |

这属于**有风险且降险手段已用尽**的方案：名称含上游商标、"鸿蒙版"后缀容易被理解
为官方中文版，且**图标与官方完全一致**（已不再有"外观可区分"这一层缓冲）。
逐项风险与替代方案见 `README.md` 第 8 节。

> 折中建议（成本很低）：若想在不改名的情况下保住一点区分度，可以给图标叠一个
> 「鸿蒙」角标之类的可识别改动——但请注意**改动图标只能降低"混淆"的观感，
> 不能解决名称商标问题**；真正的解法仍是下面第 1 步的书面许可。

要把它做成"可解释"，按优先级做三件事：

1. **发许可申请**：用 `docs/upstream-permission-request-ready.md`（已按你的身份预填好，
   只差邮箱与仓库地址）发到上游 **GitHub Discussions**
   （`https://github.com/EtchDroid/EtchDroid/discussions`）——
   注意上游 `blank_issues_enabled: false`，**发不了空白 Issue**，只能用 Discussions。
   发出后把链接与截图存进 `docs/permission-evidence/`，提交应用市场时放进
   "审核备注 / 补充材料"。**这是最有效的一步。**
2. **商店描述写清楚**：开头就写"非官方移植，基于 GPLv3 开源项目 EtchDroid"，
   不要出现"官方""正版""作者授权"等字样（未获许可时这属于虚假陈述，比商标本身更严重）。
3. **别删 App 内的非官方声明**：它是善意最直接的证据。

拿不到许可或不想担风险时，改走 B 方案：换成不含 `EtchDroid` 的独立名称
（例如"镜像写入助手""OTG 启动盘制作"）+ 完全自绘图标，商标风险基本清零，
GPLv3 合规不受影响。

**② 包名 bundleName（中风险）**

当前包名是 `eu.depau.etchdroid.harmony`，其中 `eu.depau` 是**上游作者的
反向域名**。这属于冒用他人标识，且上架后包名唯一、无法更改。建议改为你自己的
标识，例如 `cn.<你的标识>.etchdroid` 或 `com.<你的标识>.<应用名>`。

> 改包名需要同步修改 `AppScope/app.json5`、`build.sh` 里的 `BUNDLE_NAME`，
> 然后重新构建签名。可以让我一次性改完。

### 3.4 审核可能追问、建议提前准备的材料

- **《开源软件使用与授权说明》**：一页纸，写明
  "本应用是 EtchDroid（https://github.com/EtchDroid/EtchDroid，GPLv3）的
  HarmonyOS 移植版本，附 LICENSE 与 NOTICE，源代码发布于 <你的仓库>"，
  并附上 `LICENSE`、`NOTICE` 两个文件。
- **功能说明**：应用把用户选择的 ISO/IMG 镜像写入 USB 存储设备；写入前需用户
  授权 USB 访问；写入会清空目标设备，界面已有警告提示。
- **权限必要性说明**：后台运行（长时任务）用于保证数分钟的写入过程不被中断。

## 5. 建议的稳妥路线（按顺序）

1. **先发许可申请**（见 3.3 ①，名称与图标都还没拿到授权）→ 定名字 → 改
   `bundleName` → 重新构建签名（我可以代做）。
2. 建一个**公开源码仓库**（Gitee 在国内访问更稳），把本目录全部内容推上去，
   确认按 README 能构建出 HAP。
3. 填好 `NOTICE` 与 `docs/privacy-policy.md` 的占位内容，把隐私政策发布到公网。
4. 申请软著（说明书如实写明基于 EtchDroid 移植）；同时办理 APP 备案。
5. 在华为开发者联盟完成实名 → 创建应用 → 填写备案号、隐私政策 URL、权限说明 →
   上传 HAP → 附上 LICENSE / NOTICE / 开源授权说明。
6. 上架后：**每次发新版，都要同步更新公开仓库的源码**（GPL 义务不因上架而消失）。

## 6. 一句话总结

这个应用的法律风险**不在技术，而在"标识"和"许可证"**：

- 许可证：必须 GPLv3 开源 → 已用 `LICENSE` + `NOTICE` 落地，剩下的是"建公开仓库"。
- 标识：名称含 `EtchDroid`、图标与上游逐字节相同、包名用了上游作者域名 →
  这三项都还没解决，是当前最大的下架/投诉风险；拿到许可前上架，请如实标注
  "非官方移植"。
- 行政：软著 + APP 备案 + 隐私政策 + 权限说明 → 个人开发者逐项办，缺一不可。
